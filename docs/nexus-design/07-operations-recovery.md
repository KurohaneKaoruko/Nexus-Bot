# 18. 运维控制、配置、Flags 与灾难恢复

## 18.1 自动化仍需要可控的操作面

自治 Bot 不代表无法干预。建议给开发者一个受约束的操作层：配置项、功能开关、房间策略覆盖、Flags、可视化和低频命令。它们用于表达目标或限制，不应绕过世界模型和行动仲裁层直接产生任意游戏动作。

## 18.2 配置分层

建议按以下优先级合并配置：

1. `defaults`：代码内安全默认值；
2. `globalPolicy`：文明级储备、风险与 CPU 配置；
3. `roomPolicy`：特定房间的防御、采集或发展策略；
4. `taskOverride`：短期紧急指令，有截止 Tick；
5. `debugOverride`：仅在测试环境启用，不能无意间进入生产。

所有临时覆盖都应有 owner/reason/createdAt/expiresAt。未设过期时间的调试旗标容易变成永久隐患。

## 18.3 Flags 的使用方式

Flags 可以作为可视化与人类指令入口，例如标记“重点侦察区域”“临时禁采”“重点防守”“建议撤出”“施工禁区”等。建议采用白名单命名规范和明确含义：

- 解析 Flags 时先验证名称、颜色/辅助颜色或标签约定；
- 生成结构化 `OperatorCommand`；
- 检查指令权限、作用范围、过期时间与冲突；
- 写入策略覆盖或任务，而不是在 Flag 解析器里直接调用 `attack`、`claim` 等动作；
- 指令生效与结束都在视觉面板/日志中反映。

不要把用户随意放置的任意 Flag 名称都当成可执行代码参数；未知名称默认忽略并限频告警。

## 18.4 Feature flags 与安全开关

高级功能应该可独立禁用：`enableMarketTrading`、`enableRemoteMining`、`enablePowerOps`、`enableNukerPlanning`、`enableAdaptiveTuning` 等。配置关闭后，需要停止新建相关任务，并优雅处理已存在任务/资源预留，不能只停止调用代码而留下永久占用。

对高风险操作（市场大额交易、Claim 新房间、发射 Nuker、投入高成本 Boost 军团）设计双重条件：策略满足 + policy gate 通过。Gate 可以要求资源储备安全、目标 Intel 新鲜、操作在允许白名单且预算未超限。

## 18.5 运维命令

建议建立可复现且有版本的命令接口，例如：

- 查看某房间战略状态、关键库存与任务队列；
- 显示某 Creep 的任务、能力画像、路径状态和上次失败；
- 手动释放指定任务租约；
- 重新扫描可见房间结构；
- 清理过期缓存（不清除关键战略知识）；
- 开启/关闭某个模块的诊断日志；
- 输出 CPU 和 Memory 使用摘要。

命令只调用公开服务方法，并记录 Tick 和参数；不要用任意 eval 字符串成为操作面的核心。调试命令必须可安全重放或有明确的非幂等警告。

## 18.6 灾难恢复等级

### Level 1：单机体死亡

回收任务租约、清理 UnitRecord、重新评估替补需求。全局不应受影响。

### Level 2：房间经济局部失效

例如 Source 采集断线、运输链堵塞或 Spawn 暂时无能源。暂停可选任务，确保基础采集与运输恢复，必要时重建关键施工项。

### Level 3：房间遭受袭击

触发 ThreatModel 与防守政策；停止风险不可接受的远程任务，保护或撤回关键单位，按损失预算重分配资源。

### Level 4：主殖民地失守/所有 Spawn 丢失

如果账户仍有可用单位或另有可恢复立足点，按保留的全局目标、GCL 与剩余资产规划恢复；若必须使用游戏的 Respawn 流程，考虑到 GCL 等账户进度与房间资产不是同一回事。具体重生条件及等待时间以当前官方 Respawn 规则为准。

### Level 5：Memory/schema 受损

先尝试版本迁移与字段级修复；保留仍有效的战略姿态、房间目标和资源承诺，重建可推导数据；如果无法安全恢复，清理受影响子系统并以 `survive` 姿态启动。

## 18.7 自动恢复原则

- 先恢复最小经济闭环，而不是立刻恢复全部扩张与工业系统；
- 不在缺少情报的情况下重复把昂贵单位送入同一危险路线；
- 任何高成本操作使用有限重试；
- 每次自动恢复记录原因、时间、尝试次数与结果；
- 恢复过程中如果 CPU 不足，保留关键动作、跳过统计和优化。

## 18.8 遥测面板最低内容

- 全局战略姿态与当前主要目标；
- 房间列表、RCL/owner/Intel 新鲜度/威胁级别；
- 能源净变化、预留与可用库存；
- Spawn 空闲情况与生产队列；
- 活跃任务数、租约超时、任务失败类别；
- CPU 使用、Bucket 变化、Memory 大小；
- 过去窗口的单位损失、关键结构损失与恢复时间。
