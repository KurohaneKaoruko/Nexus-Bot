# 02. 经济、孵化与角色：main 变体运行现状

> 2026-10-28 代码走查，未运行代码。汇总进 `../12-legacy-bot-migration-map.md` §25.3.2 / §25.3.3。
> 状态口径：主线 / 混合 / 旧代码在跑 / 死代码 / 缺失（定义见 `../12-legacy-bot-migration-map.md` §25.1）。

## 概要

- **两套孵化器每 tick 都在跑**，都会调用 `spawnCreep`：旧任务池（`room.SpawnWork`）与主线 `spawnDirector`。`features.ts:41` 注释称孵化池 spawn 链「已退役」，与代码不符。
- **每个经济角色都在两套驱动之间切换**：持有任务租约时由主线 `runCreep` 驱动；没有 `taskId` 时由 Rosmarin 旧角色 `exec()` 驱动。分配器只看身体部件（`tasks/allocator.ts:80-125`，不看角色），任何单位都可能被主线任务接管，租约结束后又回到旧代码。

## 活路径上的旧 Memory 键

- **`Memory.Nexus` 旧域**（`core/store/accessor.ts`）：`MissionPools`（孵化 / 运输 / 管理 / 建造 / boost / 采矿池，`MissionPools.ts:58`）、`RoomData`（mode、center；`spawnControl.ts:13`、`Room/baseFunction` 的 `getCenter`）、`LayoutData`（`coreDepot.ts`）、`StructData` 与 `TeamData`（`boostMission.ts`）、`funnelCooldown`（`FunnelModule`）、`warmode`（`spawnRules`）。
- **`room.memory`**：`energyState`、`energyStateTick`、`energyReserve`（至少每 5 tick 写，`Room/baseFunction.ts:286-325`）；`defend`、`defendUntil`、`breached`（spawnRules、roomWorkforce、energyLogistics）；`sourcePosCount`、`building`、`buildingTick`、`upgradeTiming`、`mode`。
- **重复记账**：`sourceTiming` 与 `upgradersStarved` 两边各一份——`Memory.Nexus.rooms[r].sourceTiming`（`agentSystem.ts:479`）与主线 `workforce.registerUpgraderStarve`，并行于旧 `room.memory` 版本（`roomWorkforce.ts:169`）。
- **`creep.memory`**：`role`（两套孵化器都写，`exec()`、`creepTickIndex` 与旧计数读）；`home`（旧）与 `homeRoom`（主线），`creepTickIndex` 两者都认；旧专用：`targetSourceId`（用得最多）、`working`、`bind`、`dontPullMe`、`sourceRoom` / `targetRoom`、`cache`（`ensureMemoryCache`）、`spawnTick` / `downgraded`、`boostmap`、`fsm`（miner）、`_moveToRoomState`；主线用 `taskId`、`mode`、`relayedTick`、`waitStart`，存在 `Memory.creeps` 而非 `Memory.Nexus`。
