# API-10：测试、验收和发布清单

## 10.1 类型检查与构建

- [ ] 使用锁定的 Node.js / npm / TypeScript / `@types/screeps` 版本。
- [ ] `npm ci` 在干净环境成功。
- [ ] `tsc --noEmit` 或项目等价 typecheck 通过。
- [ ] 游戏运行时代码未错误依赖 Node / DOM / 文件系统 API。
- [ ] 未通过 `any`、`@ts-ignore` 或过宽类型掩盖原生 API 不匹配。
- [ ] 自定义 `Memory` 声明与 Bootstrap schema 保持一致。
- [ ] 输出 bundle 使用部署环境支持的语法和模块格式。

## 10.2 原生 API 集成测试

每种重要原生调用至少包括一个成功测试和一个失败/边界测试：

- [ ] `Creep.harvest`：有效 Source、距离不足、无 WORK / Source 耗尽等适用场景。
- [ ] `withdraw` / `transfer`：资源不足、目标满、目标对象失效。
- [ ] `build` / `repair` / `upgradeController`：距离、资源、目标限制。
- [ ] `moveTo` / `PathFinder.search`：跨房间、不可通行地形、不完整路径、动态阻挡。
- [ ] `spawnCreep`：有效身体、能源不足、Spawn 忙碌、名称冲突、RCL/能源预算约束。
- [ ] `Tower` 行动：能源不足、目标不存在、多个目标优先级。
- [ ] Controller/Safe Mode：不同权限/冷却/可用状态。
- [ ] Terminal/Market：交易能源不足、目标无效、终端冷却、订单变化。
- [ ] Lab/Factory/Power：配方/资源/冷却/技能相关条件。

## 10.3 自定义 API 合约测试

### Memory

- schema 初始化正确；旧 schema 逐步迁移；损坏条目可隔离；重复迁移不会重复破坏数据。
- 主 Memory 与 segment 数据大小有上限；过期数据会回收。

### TaskBoard

- 重复 `upsert` 不会创建无限重复任务。
- 过期租约、死亡 owner、无效目标会被回收。
- 无效 owner 无法完成他人的任务。
- 完成/失败/取消终态不会静默回到活动状态。

### Allocator

- 不会把没有必要部件的 Creep 分配到任务。
- 有效任务不会每 Tick 无条件换人。
- 旅行时间、风险、TTL、负载和任务容量参与评估。

### ActionBroker

- 同一 `dedupeKey` 不重复提交。
- 冲突 pipeline 的规则有测试。
- 原生返回码被保存并正确映射到重试/重规划/终止。
- 计划中的闭包/游戏对象不会写入 Memory。

### EconomyLedger

- 资源不会被多次预留超过可用量。
- 承诺数量大于现有库存时，系统拒绝或按明确策略降级。
- 取消任务、失败和过期都正确释放预留。

## 10.4 长时间运行测试

建议至少覆盖：

- 连续多个现实小时的低风险稳定运行；
- 多个普通 Creep 老化、死亡与替补；
- Spawn 能源短缺以及经济恢复；
- 房间短时失去视野、Intel 老化和重新侦察；
- 敌人出现、撤退和防御恢复；
- 路线变化、建筑阻路、单位卡住；
- CPU Bucket 下降后的降级行为；
- Memory 清理和 schema 升级；
- 多房间阶段中一个 Room Cluster 出错而其他房间继续运作。

## 10.5 发布门槛

不能以“TypeScript 能编译”作为发布的唯一标准。发布必须同时满足：

1. 类型检查通过。
2. 单元与模拟集成测试通过。
3. 关键任务成功率达到项目阈值。
4. CPU 平均值和峰值有预算余量。
5. Memory 大小与增长速度可控。
6. 任务失败/过期率没有持续上升。
7. 没有无法恢复的异常循环或日志风暴。
8. 发布包可以回滚到上一已验证版本。
9. 目标官方/私服环境明确记录。
10. 所有未完成模块均有功能开关，不会被误当成完成实现。
