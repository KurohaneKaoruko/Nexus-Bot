# Ring 升级块吞吐塌缩（K.ring 单箱围堆形态）

- 优先级: P2
- 状态: 已定位结构性上限；ring 与混合形态（K.ringTo）均实测负收益，默认关闭，保留为实验旋钮
- 引入: K.ring 变体（主代码 cc 形态移植：单箱 (17,27) + 围堆 + 升级工接力传递）

## 结论

17 轮迭代后 ring 最优形态（v17：双 CARRY + fed 0.62 + 槽位静态 + lanePileMax 3000）
20k 4 组 mean **989,033**，vs 融合基线 **1,072,701**（-7.7%）。ring:0 默认路径与
融合基线 4 组**逐位一致**（1067305/1071434/1075888/1076177），融合无损。

## 结构性根因（非参数可修）

1. **卸货带宽**：3 箱时车道 7 格邻箱（hauler 1 tick 卸完即走），单箱仅 3 格
   → 满载 hauler 排队 → 矿端周转变慢 → harvested -51k。
2. **接力 duty 天花板**：传递供能的升级工 duty 上限 ~75%（取能/传递占 tick），
   自取箱邻槽 ~95%。13 工 × 75% ≈ 10 工 × 95%，但多 3 工的孵化/续命开销。
3. **缓冲减半**：单箱 2000 vs 三箱 6000，峰值流溢到车道 pile 常驻 ~3k，
   decay 3-6/t 白损。

## 途中证实的坑（勿重蹈）

- hauler 满载 1250 直接 transfer 给 1-2 CARRY 的升级工 = 滴灌 25t，车道滞留
  吞吐崩塌（v7/v8 173k）——整包必须落箱或 pile，传递只在升级工之间。
- 周期性槽位重排 = 永久换位混沌 + CPU 20-28ms/tick 桶溢出（v12 upRate 6）。
- `__K={ring:0}` 前缀会禁用 PRIVATE_PROFILE 自动选择（configure 的
  `!globalThis.__K` 条件），A/B 必须用构建期开关而非 __K 注入。

### 定性结论（混合线关闭）

1. **L3 领先的真实来源是省 10k 箱体建造能量，不是 ring 升级形状**：
   boxEarly:1 把三箱早建后 L3 从 3,063 退回 3,349-3,372（比基线还慢 90t）。
   ring 槽位/接力在 RCL 1-3 的净效果约 **-90~-180t/段**（fed 0.62 上限 +
   双 CARRY 身体少 1 WORK + 接力 duty 天花板）。
2. **切换成本不可消除**：无论切点 RCL3/4，两翼箱 10k 建造都撞扩展建造高峰，
   L3→L4 段 +200~400t；提前到 RCL3 只是把成本摊薄，无法转正。
3. **legacy 槽位强依赖三箱供能**：仅中心箱时 R23 槽位断供（box4:4 实测
   L3→L4 段崩坏、L4 方差 6.1k-7.5k），推迟建造必须配 ring 槽位，而 ring
   槽位自身负收益——两个必要条件互斥，混合形态无可行解。
4. 后段（RCL4-5）另有 ~300t 残留亏损：flip 前孵化的 ring 身体（少 1 WORK）
   在役至 ~flip+1500t，且 13 槽→11 槽的超编期 spawn 门锁死换代。
