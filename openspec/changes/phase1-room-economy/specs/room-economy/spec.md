# Spec Delta

## Purpose

单房间能源闭环的任务源与优先级政策：把房间观测转化为采集、搬运、补给、升级、建造任务，保证 Spawn 不断能、缺口能自愈、劳动力有活干。

## ADDED Requirements

### Requirement: 稳定采集任务
系统必须按 Source 建立稳定的采集任务（去重键含房间与 Source ID），并以该 Source 的可用工作位数为任务容量；容量已满或 Source 不可达时不得继续创建重复采集任务。

#### Scenario: 按 Source 去重
- **WHEN** 某 Source 已有存续的采集任务
- **THEN** 不再为同一 Source 创建第二条采集任务

#### Scenario: 工位容量互斥
- **WHEN** 采集任务的持有者数量达到 Source 的工作位容量
- **THEN** 任务不再接受新分配，多余劳动力流向其他任务

### Requirement: 补给与搬运任务
系统必须持续检测 Spawn/Extension 的能量缺口并生成补给搬运任务，关键供能结构享有最高补给优先级；目标容量已满或缺口消失时任务及时终结。

#### Scenario: 缺货自愈
- **WHEN** Spawn/Extension 能量低于容量且无在途补给
- **THEN** 产生对应的补给任务并优先分配

#### Scenario: 满仓即终结
- **WHEN** 补给任务的目标在执行前已被填满
- **THEN** 任务被清理，不继续占用劳动力

### Requirement: 升级与建造任务
系统必须维持 Controller 升级任务（有劳动力即持续产出），并仅为已存在的工地生成建造任务；工地建成或消失后任务终结，不再为不存在的工作生成任务。

#### Scenario: 工地驱动建造
- **WHEN** 房间内存在工地
- **THEN** 按工地生成建造任务（去重键含工地 ID）

#### Scenario: 建成即终结
- **WHEN** 工地建成或被移除
- **THEN** 对应建造任务终结，不再重生

### Requirement: 能源优先级政策
任务优先级必须体现能源政策稳定序：Spawn 供能补给最高，其后为采集、搬运，建造与升级次之；当净收入不足以同时支撑时，建造/升级劳动力自动让位于补给与采集，能源充裕时才恢复投入。

#### Scenario: 紧缺时让位
- **WHEN** Spawn/Extension 严重缺能且劳动力不足
- **THEN** 升级/建造任务不被分配，补给与采集任务优先获得劳动力

#### Scenario: 充裕时恢复
- **WHEN** 能源库存与供能恢复正常
- **THEN** 升级/建造任务重新进入分配

### Requirement: 无重复无限任务
全部任务源的总产出必须受去重与对账约束：不允许同一意图的任务无限堆积；长期不可执行的任务在尝试上限或截止后终止并计入统计。

#### Scenario: 不可执行任务终止
- **WHEN** 某任务连续失败达到上限或长期无进展
- **THEN** 任务终止并计入失败统计，不再占用分配轮次

#### Scenario: 任务总量有界
- **WHEN** 任务源连续多个 Tick 运行
- **THEN** 活动任务数与可见工作对象数量同阶，不随时间无限增长
