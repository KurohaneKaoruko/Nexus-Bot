# Spec Delta

## Purpose

路口拥堵检测：统计单位移动的堵塞计数、等待时长与路口堵塞频率，为拥堵响应与路径重估提供信号；本期只做检测与分级响应，不重写既有交通管理。

## ADDED Requirements

### Requirement: 堵塞滚动统计
系统必须按滚动窗口统计每个单位的连续阻塞次数与等待时长，以及路口/瓶颈格的堵塞频率；统计容量有界，过期数据淘汰。

#### Scenario: 阻塞累计可见
- **WHEN** 某单位连续多 Tick 无法进入下一格
- **THEN** 其连续阻塞计数与等待时长增长并可被查询

#### Scenario: 统计有界淘汰
- **WHEN** 单位恢复移动或统计超过窗口长度
- **THEN** 计数被重置或按窗口淘汰，不随 Tick 无界累积

### Requirement: 拥堵分级响应
连续阻塞必须触发分级响应：首次仅等待，连续阻塞后尝试换位/让路或路径重估，超时后提升路径成本或释放任务；每次重试必须有上限。

#### Scenario: 连续阻塞升级处理
- **WHEN** 某单位连续阻塞超过阈值
- **THEN** 触发换位或路径重估，而非每 Tick 重复相同移动指令

#### Scenario: 重试有上限
- **WHEN** 分级响应重试达到上限仍无法通行
- **THEN** 单位释放当前任务或该路线成本被提升，不再无限重试

### Requirement: 路口堵塞热点识别
系统必须识别反复发生堵塞的路口/瓶颈格，其频率数据可供路径成本与道路规划参考；热点记录有界。

#### Scenario: 热点频率累计
- **WHEN** 同一路口格反复发生多单位堵塞
- **THEN** 该格的堵塞频率上升并被识别为热点

#### Scenario: 热点数据可消费
- **WHEN** 存在被识别的拥堵热点
- **THEN** 其频率数据可被路径成本与建设规划读取
