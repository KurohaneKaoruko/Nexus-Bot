# Spec Delta

## Purpose

房间资源账本：区分库存与可用库存、以滚动窗口估计生产/交付速率、记录资源预留承诺，使各系统不会重复花掉同一笔能源，并为经济模型提供可信的流量数据。

## ADDED Requirements

### Requirement: 库存与可用库存区分
账本必须区分每房间每种资源的库存（可见结构与 Creep 携带的估算）与可用库存（扣除已预留承诺后的数量），且 `available(resource, room)` 不得大于库存。

#### Scenario: 预留扣减可用量
- **WHEN** 某房间能源库存 1000 且已有 400 被有效预留
- **THEN** 查询可用库存返回 600

#### Scenario: 预留不超发
- **WHEN** 可用库存不足以满足新的预留请求
- **THEN** 该预留被拒绝或仅部分成立，可用库存不为负

### Requirement: 预留承诺生命周期
账本必须支持预留的创建（所有者、资源、数量、过期时间）、按实际用量的提交、按原因的释放；过期预留必须被自动清理，不得永久占用可用库存。

#### Scenario: 提交按实际用量
- **WHEN** 持有者提交预留且实际用量少于预留量
- **THEN** 差额部分返还为可用库存

#### Scenario: 过期自动清理
- **WHEN** 某预留超过其过期时间仍未提交
- **THEN** 预留失效，对应数量回到可用库存，并计入过期统计

### Requirement: 滚动速率估计
生产速率与交付速率必须以滚动窗口估计，单 Tick 瞬时值不得被当作稳定产能；窗口为有界固定长度。

#### Scenario: 瞬时尖峰不平滑破坏估计
- **WHEN** 某 Tick 交付量异常高于近期水平
- **THEN** 滚动窗口均值变化平缓，不因单 Tick 尖峰翻转瓶颈判断

#### Scenario: 速率随持续变化收敛
- **WHEN** 采集能力持续提升若干窗口周期
- **THEN** 估计的生产速率收敛到新的水平

### Requirement: 账本存储有界
账本的持久化状态必须有界：预留记录随过期清理，速率窗口为固定容量；长时间运行后账本占用不随时间无界增长。

#### Scenario: 长期运行占用稳定
- **WHEN** 系统连续运行数千 Tick
- **THEN** 账本相关 Memory 占用与房间数、活跃预留数同阶，不随 Tick 数增长
