# Spec Delta

## Purpose

威胁观测与评分：把敌方单位与防御结构状态纳入感知快照，按房间产出带新鲜度的威胁摘要与评分，区分 NPC 与玩家敌人，并沉淀有界战损统计。

## ADDED Requirements

### Requirement: 敌方与防御结构观测入快照

感知每 Tick 必须把可见敌方 Creep（位置、主人、存活部件构成、Boost 迹象）与己方防御相关结构（塔及能源、墙体/城门耐久、受损建筑）聚合进房间快照；下游一律读快照，不各自扫描房间。

#### Scenario: 敌方单位可见即入快照

- **WHEN** 可见房间内出现敌方 Creep
- **THEN** 该单位的位置、主人与部件构成进入当 Tick 房间快照，可供威胁评分消费

#### Scenario: 防御结构状态入快照

- **WHEN** 房间存在塔、墙体、城门或受损建筑
- **THEN** 其能源/耐久状态进入当 Tick 快照，塔控与维修规划无需再次 find

### Requirement: 威胁评分与敌情分类

系统必须按房间产出威胁摘要与威胁分；评分必须基于部件构成推导的能力（攻击/治疗/耐久）与对关键资产（Spawn/Controller/存储/矿工）的接近度，不得只数单位数量；NPC Invader 与玩家敌人必须分类记录，响应强度按类别区分。

#### Scenario: 部件构成影响威胁能力

- **WHEN** 两个敌方 Creep 数量相同但一个以治疗部件为主、一个以攻击部件为主
- **THEN** 二者的威胁能力摘要不同，评分与响应不同

#### Scenario: 接近关键资产提高威胁

- **WHEN** 敌方向 Spawn 或采集矿工逼近
- **THEN** 其对关键资产的威胁度上升并反映在威胁分与原因摘要中

#### Scenario: NPC 与玩家敌人分类

- **WHEN** 房间同时出现 NPC Invader 与玩家敌人
- **THEN** 威胁摘要按类别分别记录，不合并为同一种威胁

### Requirement: 威胁新鲜度与衰减

威胁摘要必须携带最近观测 tick 与置信度；失去视野后置信度随未观测时间衰减，过期威胁不得当作实时事实维持防御状态。

#### Scenario: 敌人消失后威胁衰减

- **WHEN** 敌方单位被击杀或离开可见范围
- **THEN** 房间威胁分随时间衰减至无害水平，不再维持防御响应

#### Scenario: 失视数据不作实时事实

- **WHEN** 威胁记录已超过有效期仍无新观测
- **THEN** 该记录被降置信处理或清除，不触发新的防御任务

### Requirement: 战损统计有界

系统必须统计战损与防御开销（本单位损失、击杀敌方数、塔能源消耗），统计有界可查询，不随 Tick 无界增长。

#### Scenario: 战损可查询

- **WHEN** 威胁窗口内有单位战死或塔开火
- **THEN** 对应战损/开销计数递增，可经控制台或 HUD 查询

#### Scenario: 统计容量有界

- **WHEN** 长时间多次战斗
- **THEN** 战损统计容量保持有界（按窗口折叠或保留最近记录）
