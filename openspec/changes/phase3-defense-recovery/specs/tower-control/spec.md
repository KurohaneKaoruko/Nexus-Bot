# Spec Delta

## Purpose

塔控制：按威胁排序选择开火目标、多塔合理分配火力、维持塔能源最低储量，塔行动统一经行动仲裁层提交并记录结果。

## ADDED Requirements

### Requirement: 塔目标选择排序

塔必须按「即刻危险 × 战略价值 × 击杀可行性」选择目标，而不是只打距离最近的敌人；对正在威胁关键结构或能持续治疗敌方核心的敌人优先，敌方治疗能力必须纳入击杀可行性评估。

#### Scenario: 威胁关键资产的敌人优先

- **WHEN** 一个敌人在 Spawn 附近、另一个在房间边缘
- **THEN** 塔优先攻击对关键资产构成即刻危险的敌人

#### Scenario: 敌方治疗者纳入评估

- **WHEN** 敌方编队含治疗单位且其治疗量会抵消塔伤害
- **THEN** 目标选择考虑治疗压制（优先控制治疗者或放弃无效集火），而非机械轮流开火

### Requirement: 多塔火力分配

多座塔必须协调目标分配：对确定能快速击杀的低价值目标不过度集火，火力优先覆盖多个有效目标。

#### Scenario: 不过度集火

- **WHEN** 房间有多座塔与多个敌方目标，某低价值目标已被足够火力覆盖
- **THEN** 剩余火力分配给其他有效目标，而非全部塔重复锁定同一目标

### Requirement: 塔能源最低储量政策

塔必须维持配置的最低能源储量：低于储量线时停止非关键用途（修缮）只保留开火，并生成高优先级补给任务；补给优先级高于普通搬运。

#### Scenario: 低能源停修保开火

- **WHEN** 塔能源跌破最低储量线且有受损友方建筑
- **THEN** 塔不再执行修缮，能源只用于对敌开火

#### Scenario: 塔补给优先

- **WHEN** 塔能源低于补给触发线
- **THEN** 产生补塔任务且优先级高于普通 haul，账本预留正确

### Requirement: 塔行动统一提交

塔的每 Tick 行动（攻击/治疗/修缮）必须作为行动提案经统一行动仲裁层提交：每塔每 Tick 至多一个意图，执行结果码被记录并参与失败分类。

#### Scenario: 每塔每 Tick 单一意图

- **WHEN** 同一座塔同一 Tick 被提交多个行动提案
- **THEN** 仲裁层按优先级保留一个，不重复调用原生 API

#### Scenario: 结果码记录

- **WHEN** 塔行动返回非 OK 结果码
- **THEN** 该结果按失败类别记录，可被统计与排障查询
