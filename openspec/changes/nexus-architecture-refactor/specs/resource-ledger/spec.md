# Spec Delta

## Purpose

资源五态账本：经济系统以统一账本回答"有什么、缺什么、流向哪、哪里饥饿、哪里瓶颈"；区分实际库存、已预留、在途、已承诺与预计收入，为孵化/建造/升级的供给决策提供真实可用量。

## ADDED Requirements

### Requirement: 五态分账
经济账本 MUST 对关键资源（至少能量）按房间维护五态账：观测库存（Observed）、可用量（Available）、已预留（Reserved）、已承诺（Committed）、已消耗（Consumed）；可用量 = 库存 − 预留 − 承诺，预计收入单列。一切供给决策 MUST 基于可用量而非裸库存。

#### Scenario: 预留不吃库存
- **WHEN** 任务预留了 400 能量而房间库存 500
- **THEN** 后续供给决策看到的可用量为 100，不发生超发

#### Scenario: 双花被拒
- **WHEN** 两个任务同 Tick 请求预留同一笔能量且总额超过库存
- **THEN** 仅先到/高优先级者成功，后者预留失败可感知

### Requirement: 预留生命周期与泄漏防护
预留 MUST 绑定其来源任务/命令：任务终结（完成/失败/过期/取消）或命令失败时预留 MUST 同步释放；账本 MUST 检出超龄预留并强制回收，防止可用量被泄漏的预留永久侵蚀。

#### Scenario: 任务失败即释放
- **WHEN** 持有能量预留的任务失败
- **THEN** 该预留立即回到可用量

#### Scenario: 超龄预留回收
- **WHEN** 某预留超过配置的最大保留时长仍未兑现
- **THEN** 账本强制回收该预留并计数告警

### Requirement: 收入估计口径统一
采集收入、外矿收入、预订加成 MUST 使用统一折算口径（如未预订源按减半折算）；一切基于收入的定编/孵化决策 MUST 引用同一口径，杜绝同房不同数。

#### Scenario: 收入口径一致
- **WHEN** 定编计算与孵化门同时读取某房间采集收入
- **THEN** 两处得到的数值一致

#### Scenario: 未预订外矿减半
- **WHEN** 外矿源无预订
- **THEN** 账本按减半口径计入预计收入，不高估

### Requirement: 饥饿与瓶颈可观测
账本 MUST 维护按房间的饥饿事件（需求长时间得不到供给）与瓶颈指标（库存满/空、链路断供）供遥测查询；MUST NOT 无界持久化流水明细到 Memory。

#### Scenario: 饥饿可查
- **WHEN** 某房间升级供给长期低于需求
- **THEN** 遥测能定位饥饿房间、持续时长与缺口量级
