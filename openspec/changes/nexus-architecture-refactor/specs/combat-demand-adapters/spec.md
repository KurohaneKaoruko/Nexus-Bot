# Spec Delta

## Purpose

战斗体系收编：防务转为威胁驱动的需求发生器（threat detection → demand → intent），编队战斗保持内部算法资产、经 Adapter 进入命令边界；消除防务/编队与任务系统的双控制。

## ADDED Requirements

### Requirement: 防务是需求发生器
防务系统 MUST 以威胁模型为输入产出防务需求（塔动作、安全模式、守卫编制）与对应意图；防务 MUST NOT 内嵌单位直操逻辑；塔与安全模式类结构动作 MUST 经命令边界提交。

#### Scenario: 塔动作经边界
- **WHEN** 威胁模型判定塔应攻击/治疗/维修
- **THEN** 以结构意图提交命令边界执行，结果可查询

#### Scenario: 威胁升级驱动编制
- **WHEN** 威胁等级跨过配置阈值
- **THEN** 防务向孵化/任务系统提出守卫编制需求，而不是自行生产或直操单位

### Requirement: 编队经 Adapter 收编
编队模块 MUST 保持其内部战斗算法（阵型、集火、治疗链、绑伴）不被重写，但其一切原生动作调用 MUST 经编队 Adapter 汇入命令边界；编队单位的所有权由 Adapter 持有。

#### Scenario: 编队动作不绕界
- **WHEN** 编队单位执行攻击/治疗/移动
- **THEN** 原生调用发生在 Adapter 汇入的命令路径上，编队核心逻辑内无直连调用

#### Scenario: 算法资产保全
- **WHEN** Adapter 化完成
- **THEN** 编队的阵型/集火/治疗策略行为与收编前等价（场景回归通过）

### Requirement: 防务与任务系统互斥控制
同一单位 MUST NOT 同 Tick 既受任务系统驱动又受编队/防务直操；编队解散或槽位收缩时其单位控制权 MUST 归还任务系统，交接期 MUST 无行为真空（控制权先归还再释放任务）。

#### Scenario: 交接无真空
- **WHEN** 编队解散
- **THEN** 成员单位的任务被取消/释放，控制权即时归还任务系统，下一 Tick 即可被再分配

#### Scenario: 双驱被拒
- **WHEN** 编队尝试直操一个任务系统持有的单位
- **THEN** 所有权检查拒绝该命令并记录冲突
