# Spec Delta

## Purpose

孵化管线单源决策：一切单位生产统一为"需求 → 仲裁 → 体型编译 → 队列 → 孵化命令"管线；角色定义唯一来源；孵化中名单对全部子系统可见，杜绝孵化期竞态类缺陷。

## ADDED Requirements

### Requirement: 孵化需求单源仲裁
一切孵化需求（定编补充、替补、防务、扩张、编队、特需）MUST 以带优先级与模式的孵化请求进入统一仲裁；仲裁按全局约束（能量、孵化槽、预算）决策；任何模块 MUST NOT 绕过仲裁直接调用孵化 API。

#### Scenario: 直产请求走紧急通道
- **WHEN** 编队/扩张等需要即时生产的模块提出请求
- **THEN** 以 emergency/direct 模式的孵化请求进入仲裁，由孵化执行器统一执行，不绕过管线

#### Scenario: 资源竞争全局裁决
- **WHEN** 多个需求方同时竞争孵化槽与能量
- **THEN** 仲裁按优先级与全局能量约束裁决，输家进入队列或降级，不互相挤兑死锁

### Requirement: 角色定义唯一来源
单位的角色/职能定义（能力、体型策略、人口类别）MUST 由唯一定义源提供；体型编译 MUST 是纯函数（同输入同输出，无隐藏状态）；人口定编计算与孵化等待策略分离。

#### Scenario: 定义不漂移
- **WHEN** 两个子系统询问同一单位类别的体型与能力
- **THEN** 得到一致的答案，不存在第二套角色表

#### Scenario: 体型编译纯函数
- **WHEN** 相同的 RCL/能量/角色约束输入体型编译
- **THEN** 输出确定的体型方案，可离线单测复现

### Requirement: 孵化中名单可见
孵化中的单位名单（孵化建筑、单位名、剩余时间）MUST 对全部子系统以统一接口可见；依赖单位名单的子系统（清理、可视化、搬运计划、普查）MUST 能区分"孵化中"与"不存在"。

#### Scenario: 清理不吃孵化单
- **WHEN** 周期性 Memory 清理运行且有单位正在孵化
- **THEN** 孵化中单位的 Memory 记录不被删除

#### Scenario: 可视化不误杀孵化
- **WHEN** 可视化模块发现孵化中单位无角色记录
- **THEN** 只输出告警，不取消孵化

#### Scenario: 搬运不投递幽灵计划
- **WHEN** 搬运规划目标包含孵化中单位
- **THEN** 该单位被过滤或延后到出生后，不产生注定失败的投递计划

### Requirement: 孵化链路可审计
孵化管线 MUST 维护队列深度、各优先级等待时长、取消原因计数供遥测查询；孵化决策 MUST NOT 因个别模块异常而整线停摆（模块级错误隔离）。

#### Scenario: 队列健康可查
- **WHEN** 运维查询孵化管线状态
- **THEN** 可获得当前队列、各请求等待时长与最近裁决摘要

#### Scenario: 单模块异常不阻断孵化
- **WHEN** 某需求方模块抛出异常
- **THEN** 其余需求方的孵化请求照常被仲裁执行
