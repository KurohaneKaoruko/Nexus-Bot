# Spec Delta

## Purpose

产出就绪闸：以「采集面已就绪」为孵化放行前提——就绪判定每 Tick 现算、死亡自动回落；未就绪时孵化面只放行采集/应急角色，搬运开局数量与在岗采集体挂钩，杜绝「搬运倒挂吃光孵化槽」的起步死锁。

## ADDED Requirements

### Requirement: 就绪判定每 Tick 现算
房间产出就绪 = 在岗（非孵化中）采集体数 ≥ 各源采集定编合计。判定必须每 Tick 现算、无持久锁存：采集体死亡即自动回落为未就绪。源采集定编按源再生口径上限与当前孵化体型单只 WORK 折算（下限 1），并受源旁可站位数量约束；低等级房间允许多采集位，达到配置等级后收敛为一源一采。

#### Scenario: 就绪成立
- **WHEN** 各源在岗采集体数达到源定编
- **THEN** 房间判定为产出就绪，孵化闸门放行

#### Scenario: 死亡自动回落
- **WHEN** 就绪后任一源在岗采集体数跌破定编（死亡或转岗）
- **THEN** 同 Tick 判定回落为未就绪，闸门重新收紧

### Requirement: 起步孵化序列闸
房间未就绪时，孵化请求必须只放行采集面角色（采集体、万金油、升级体）；其余角色（搬运、建造、通用运输等）的孵化请求被闸除；就绪后全部角色恢复正常放行。

#### Scenario: 未就绪闸除非采集角色
- **WHEN** 房间未就绪且存在搬运/建造类孵化缺口
- **THEN** 孵化排程只受理采集面角色请求，其余请求排队等待就绪

#### Scenario: 就绪后放行
- **WHEN** 采集面补齐达到就绪
- **THEN** 被闸角色请求恢复受理，按既有优先级排程

### Requirement: 搬运开局闸
房间未就绪时，在岗搬运体数 ≥ max(1, 在岗采集体数) 即不得新增搬运孵化请求——搬运编制不得超过采集面规模，防止搬运倒挂耗尽孵化槽与能量。

#### Scenario: 倒挂防护
- **WHEN** 未就绪房间在岗 1 名采集体、2 名搬运体且存在搬运缺口表达
- **THEN** 不再新增搬运孵化请求，直至采集面就绪或搬运减员
