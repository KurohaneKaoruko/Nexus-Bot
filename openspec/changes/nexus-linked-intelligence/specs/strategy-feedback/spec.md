# Spec Delta

## Purpose

遥测反馈连结：战略决策必须建立在可量化输入之上并向上可观测——姿态/政策进 HUD 与指标，转移记录有界可查，形成「指标 → 战略 → 指令 → 行为 → 指标」的闭环验收。

## ADDED Requirements

### Requirement: 决策输入可量化
每次姿态转移的原因必须引用具体量化输入（库存数值、饥饿累计、诊断结论），不得出现无数据支撑的转移；经济诊断的既有调整（运力乘数/配额偏移/升级加成）必须保持独立运行，战略层只读不写。

#### Scenario: 转移可归因
- **WHEN** 姿态发生转移
- **THEN** 转移记录包含触发它的量化输入摘要

#### Scenario: 诊断调整不被战略覆盖
- **WHEN** 战略层读取经济诊断
- **THEN** 诊断自身的运力/配额调整机制行为不变

### Requirement: 战略可观测性
系统必须提供战略状态的可查询视图：当前姿态、储备下限、目标库存、当前优先级偏置与节流状态；HUD 必须展示姿态与政策摘要；转移记录与统计（转移次数、当前姿态驻留时长）必须有界。

#### Scenario: HUD 展示战略态势
- **WHEN** HUD 渲染房间信息
- **THEN** 可见当前姿态、储备下限与节流状态

#### Scenario: 转移记录有界
- **WHEN** 姿态反复转移多次
- **THEN** 仅保留有界数量的最近转移记录与计数统计，Memory 不无界增长

### Requirement: 闭环验收可测量
战略生效性必须可用既有经济指标验证：进入 survive 后能源净变化应在观测窗口内回正；压制非关键任务期间 Spawn 供能结构缺货不得恶化。

#### Scenario: survive 自愈
- **WHEN** 库存告急进入 survive 且压制生效
- **THEN** 后续观测窗口的能源净变化指标转为正值并最终回到 develop

#### Scenario: 压制不伤害关键补给
- **WHEN** upgrade/build 被节流期间
- **THEN** 关键结构缺货指标不因节流而上升
