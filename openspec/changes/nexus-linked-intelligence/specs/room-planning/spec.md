# Spec Delta

## Purpose

局部规划层：按房间执行的职能系统规划模块（经济，以及后续防御/扩张/工业）——读房间快照与当 Tick 战略指令，产出共享任务板任务与账本预留；职能域不称集群，集群专指多 Creep 协作编队。

## ADDED Requirements

### Requirement: 按房间的规划模块契约
任务规划必须按房间执行：各职能系统作为局部规划的独立模块注册（planning/emergency 阶段），输入为该房间的观测快照与当 Tick 战略指令，输出为共享任务板上的任务 upsert 与资源预留；同一殖民地的多个职能系统必须经共享账本协调预留，不得重复承诺同一笔资源。每个职能系统必须可被变体开关独立禁用（禁用即零 CPU）。

#### Scenario: 按房间产出任务
- **WHEN** 房间可见且经济系统规划模块启用
- **THEN** 该房间产出与快照一致的经济任务集合（采集/搬运/供能/升级/建造）

#### Scenario: 独立禁用
- **WHEN** 变体 profile 禁用某职能系统模块
- **THEN** 该模块不注册不执行，其余职能系统行为不受影响

### Requirement: 经济规划行为兼容
经济规划按房间化重构后，任务去重键、任务种类、账本预留语义必须与重构前保持一致；本期唯一的行为变化来自战略指令的优先级偏置与节流语义。

#### Scenario: 去重键稳定
- **WHEN** 同一房间同一观测主体连续多 Tick 被规划
- **THEN** 任务按既有去重键合并，不产生重复任务

#### Scenario: 主体消失回收
- **WHEN** 任务主体（工地/缺货结构/货源）消失
- **THEN** 对应任务被取消，与重构前行为一致

### Requirement: 后续职能系统可插拔
系统必须允许新的职能系统（防御/扩张/工业等）以 planning 阶段模块注册进局部规划，接收同一指令视图，而不需要修改内核调度或既有职能系统；未实现的职能系统不得产生常驻 CPU 成本。多 Creep 协作编队（集群）属单位层协作形态，与职能系统正交，不占用本层抽象。

#### Scenario: 新职能系统挂载
- **WHEN** 后续版本注册一个新职能系统模块（如防御系统于 emergency 阶段）
- **THEN** 它按房间接收快照与指令并产出任务，内核与经济系统无需改动

#### Scenario: 未接入时零成本
- **WHEN** 防御/扩张系统尚未实现
- **THEN** 系统运行中不存在为其保留的每 Tick 开销
