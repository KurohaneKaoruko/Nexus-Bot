# Spec Delta

## Purpose

殖民地名册：本方单位的存活判定与执行驱动以「全部本方单位」为口径，而不是「己方房快照里的单位」。单位身处己方房、外矿房或途中房，都被同等驱动；只有真实死亡才清理其记录与任务租约。

## ADDED Requirements

### Requirement: 名册存活口径
世界快照必须提供本 tick 全部本方单位的名册。存活判定、死亡发现、任务对账的持有者存活检查都必须以名册为准；单位离开己方房不得被判定为死亡。

#### Scenario: 单位进入外矿房
- **WHEN** 一个持有外矿任务的单位从母房走进非己方房
- **THEN** 该单位的 `Memory.creeps` 条目与 `units` 记录保留，任务租约由心跳续期，不进入 `world.dead`

#### Scenario: 真实死亡
- **WHEN** 单位上一 tick 在名册中、本 tick 不在名册中
- **THEN** 该单位进入 `world.dead`，其记录被清理，任务租约由对账释放

#### Scenario: 战损归因
- **WHEN** 母房威胁活跃期间有单位在外矿房停留
- **THEN** 该单位不被计入战损；只有真实死亡的单位才计入

### Requirement: 名册驱动执行
AgentSystem 必须遍历名册，按单位所在房取己方房快照或非己方可见房快照作为执行上下文。单位在己方房时驱动规则与变更前一致；单位在非己方房时，只有持有 Nexus 任务指针的单位由 AgentSystem 驱动，其余单位由各自原有入口驱动。外矿相关行为只能读取两种快照的共有字段。

#### Scenario: 外矿房内执行
- **WHEN** 外矿采集体位于外矿房的工位上
- **THEN** 本 tick 产出采集意图并经 ActionBroker 提交

#### Scenario: 侦察到达
- **WHEN** scout 跨入目标房并继续前往房间中心
- **THEN** scout 持续产出移动意图直到到达，不在边界出口格来回

#### Scenario: 编队单位跨房
- **WHEN** 一个编队成员（无 Nexus 任务指针）走出己方房
- **THEN** AgentSystem 不在外部房为它调用原型执行器，它的 `memory.role` 与 `targetRoom` 保留，由编队入口继续驱动

### Requirement: 己方房快照语义不变
`world.rooms` 必须仍只包含己方房快照；非己方可见房只出现在独立的 `visible` 视图中。读取 `world.rooms` 做房间级空间查询（源、工地、库存）的消费方口径不变。

#### Scenario: 家内定编不受外矿房影响
- **WHEN** 外矿房可见且有两个源
- **THEN** 家内 harvester 编制的源数加总不包含外矿房的源

### Requirement: 名册计数口径
在岗计数、替补窗口、分配器候选、拥堵记录与动作速率统计必须以名册为准，并按单位的 `homeRoom` 归属殖民地；只有「某房里有哪些单位」的空间查询使用房间快照。

#### Scenario: 外出不重孵
- **WHEN** 一个单位在外矿房执行任务
- **THEN** 母殖民地的在岗计数仍包含它，不因其外出触发补孵

#### Scenario: 外部房内续接
- **WHEN** 一个单位在非己方房完成任务
- **THEN** 它仍是分配器的候选，可被分配同殖民地的下一条任务
