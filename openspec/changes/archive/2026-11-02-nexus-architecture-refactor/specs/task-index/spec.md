# Spec Delta

## Purpose

TaskBoard 作为唯一任务事实源的性能与完整性底座：为按房间/种类/状态/执行者的查询提供近似 O(1) 索引，保证索引与任务生命周期一致、无 stale 条目。

## ADDED Requirements

### Requirement: 近似 O(1) 任务查询
任务系统 MUST 提供按房间、种类、状态、指派执行者维度的索引查询，单次查询成本与任务总量解耦（哈希/分组结构），供分配与 Agent 回查询高频使用。

#### Scenario: 分配扫描不随总量退化
- **WHEN** 任务总量增长一个数量级而单房间活跃任务数不变
- **THEN** 单房间任务分配扫描的成本不随之线性增长

#### Scenario: 按执行者回查
- **WHEN** 系统查询某执行者当前持有的全部任务
- **THEN** 通过索引直接返回，不遍历全量任务表

### Requirement: 索引与生命周期一致
任务创建、指派、状态迁移、过期、取消 MUST 同步更新索引；同 Tick 内索引查询 MUST NOT 返回已终结任务或他人已指派任务。

#### Scenario: 无 stale 索引
- **WHEN** 一个任务在同 Tick 内被创建又立即取消
- **THEN** 后续索引查询不返回该任务

#### Scenario: 过期即时不可见
- **WHEN** 任务超过 TTL 过期
- **THEN** 索引立刻将其从可认领集合移除，过期任务不再被分配

### Requirement: 生命周期完整闭环
每个任务 MUST 有终结路径（完成/失败/过期/取消）且终结后不可复活；执行者死亡或租约丢失时其任务 MUST 回收再分配；任务表 MUST NOT 因异常路径泄漏无主任务。

#### Scenario: 执行者死亡任务回收
- **WHEN** 持有任务的 Creep 死亡
- **THEN** 其任务在回收窗口内回到可分配状态

#### Scenario: 任务不复活
- **WHEN** 一个任务已按任意路径终结
- **THEN** 后续 Tick 不会再对该任务产生行为或索引命中

### Requirement: 任务账本可审计
任务系统 MUST 维护计数（在途/完成/失败/过期）供遥测查询；计数 MUST NOT 无界存储任务明细到 Memory。

#### Scenario: 遥测可查
- **WHEN** 运维查询任务健康度
- **THEN** 可获得各状态任务计数与失败原因分布摘要
