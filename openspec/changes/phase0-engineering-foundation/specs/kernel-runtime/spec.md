# Spec Delta

## Purpose

为 Nexus-Bot 提供 Tick 执行内核：以固定阶段顺序驱动每一 Tick，按 CPU 预算分级调度，隔离单模块故障，并通过分支变体的模块开关适配不同私服规则。

## ADDED Requirements

### Requirement: 阶段化主循环
系统必须以固定阶段顺序执行每个 Tick（bootstrap → 感知 → … → 遥测），且在阶段执行前完成 Memory 引导与 TickContext 构建。主循环不得因缺少业务模块而无法完成。

#### Scenario: 空房间初始化状态稳定运行
- **WHEN** 游戏以空房间、无任何存量 Memory 的状态调用主循环
- **THEN** 各阶段按序执行且无未捕获异常，同一 Tick 内 bootstrap 不重复执行

#### Scenario: 长时间连续运行
- **WHEN** 主循环连续运行数千 Tick
- **THEN** 不出现未捕获异常导致的循环中断，Memory 不无界增长

### Requirement: 模块错误隔离
每个模块必须在独立错误边界内执行：模块抛出未预期异常时，仅该模块当次执行终止，错误按模块名、Tick 与错误类别限频上报，其余模块照常执行；任何 catch 不得静默吞错。

#### Scenario: 单模块异常不扩散
- **WHEN** 某模块在执行中抛出未预期异常
- **THEN** 该模块本次终止并记录一条含模块名与 Tick 的错误，同 Tick 其余模块仍全部执行

#### Scenario: 重复错误限频
- **WHEN** 同一模块连续多个 Tick 抛出相同错误
- **THEN** 该错误日志按限频输出，不每 Tick 刷屏

#### Scenario: 连续失败熔断
- **WHEN** 某模块连续失败达到阈值
- **THEN** 该模块被暂时跳过（熔断）并告警，熔断期结束后自动恢复执行

### Requirement: CPU 预算分级与降级
内核必须将工作划分为 P0–P3 优先级带，并在剩余预算不足时按 P3 → P2 顺序跳过可延迟阶段，记录每次跳过；P0 安全行动不得被可选分析抢占。

#### Scenario: 预算不足时降级
- **WHEN** 当前 Tick 剩余 CPU 预算低于某 P3 阶段的估计成本
- **THEN** 该阶段被跳过且跳过计数递增，P0 阶段仍执行

#### Scenario: 跳过饥饿保护
- **WHEN** 某可延迟阶段被连续跳过超过其最大可延迟周期
- **THEN** 内核在后续 Tick 优先安排该阶段，避免长期饥饿

### Requirement: 分支变体模块开关
内核必须依据当前分支变体的模块开关配置决定模块注册：被禁用的模块不注册、不执行、不产生 CPU 成本。开关配置随代码版本管理；缺省变体提供全量基础模块。

#### Scenario: 禁用模块零成本
- **WHEN** 当前变体配置禁用某模块
- **THEN** 每个 Tick 该模块均不执行且不产生 CPU 成本，其余启用模块行为不变

#### Scenario: 变体间互不影响
- **WHEN** 变体 A 禁用而变体 B 启用某模块
- **THEN** 以变体 A 构建部署的服务器不执行该模块，以变体 B 构建部署的服务器正常执行

### Requirement: 限频日志与最小遥测
系统必须提供限频、限长的日志输出（含模块、Tick 等上下文字段），并维护最小遥测计数（模块 CPU 用量、错误数、预算跳过数）。日志与遥测原始数据不得无界持久化到 Memory；高频遥测摘要以房间可视化呈现，不周期性占用控制台。

#### Scenario: 遥测可查询
- **WHEN** 玩家在游戏控制台查询遥测摘要
- **THEN** 可见各启用模块的最近 CPU 用量、错误计数与跳过计数

#### Scenario: 高频摘要走房间可视化
- **WHEN** 主循环持续运行
- **THEN** 遥测摘要绘制在房间可视化 HUD 上，控制台不出现周期性遥测日志

#### Scenario: 日志历史不增长
- **WHEN** 高频事件持续发生
- **THEN** 日志输出被限频，Memory 中不保存无限增长的日志历史
