## 影响多行的五个问题（先读）

1. **旧角色与 Power Creep 走不动。**
   - 真正的移动只发生在 `Broker.run` 内：`preTickBetterMove()`（`src/modules/agents/index.ts:56`）清空待处理移动，`endTickResolve()`（`:68`）执行。
   - BetterMove 替换了 Creep 与 PowerCreep 的 `move` / `moveTo`（`src/modules/movement/index.ts:3317-3320`），调用只登记意图（`:1957`），清空在 `:3295`。
   - 同阶段模块按注册序执行，不按预算带排序（`src/core/scheduler.ts:43-51`、`src/core/nexus.ts:26-27`）。
   - 旧 `exec()` 在 **agents** 阶段运行（`agentSystem.ts:1177`），意图在 `Broker.run` 开头被清掉。
   - `Teams`、`PowerCreeps`、`Nukes`、`InterShard`、`Expansion` 是 commit 阶段模块，在 `src/main.ts` 中注册于 **Broker 之后**，意图登记在解算之后、下 tick 被清。
   - Rosmarin 在整个 tick 开头清、结尾解算（`R:src/modules/MoveModule.ts:44-48`）。
   - 结果（推断）：编队、Power Creep、aio 等单兵战斗角色，以及 manager / transporter / miner 原地不动。Broker 自己的移动（`actionBroker.ts:153` 的 `creep.moveTo`）正常。不需要移动的动作（attack / heal / boost / renew）只在单位已在范围内时生效。
2. **非任务单位只在己方房内被驱动。** 感知只保留 `controller.my` 的房（`src/modules/world/perception.ts:86-89`）；`runAgents` 只遍历这些房，`Creep.exec()` 没有其他调用方。旧角色单位与主线 claimer 出了己方房即停止被驱动。
3. **孵化了但没有执行器的角色。** `roleRegistry`（`src/modules/agents/prototype/Creep/runtime/registry.ts:28-52`）缺：`cleaner`、`dismantle`、`logistic`、`attack-claimer`、`claimer`、`aid-*`、`up-*`、`scout`、`reserver`、`power-*`、`deposit-harvest/transfer/attack/ranged`、`out-*`。活路径仍会孵出其中若干，孵出后只记 `missing-handler` 并闲置。
4. **`agentSystem.ts:1172` 的守卫无效。** `creep.unitCode in NEXUS_TASK_DRIVEN_CODES` 对 Set 用 `in`，恒为 false；实际规则是所有无 `taskId` 的单位都跑旧 `exec()`，包括主线 harvester / carrier / defender。
5. **Memory 根只有 `Memory.Nexus`（大写）。** 主线类型化 Memory（`ctx.memory`）写在 `Memory["Nexus"]`（`src/core/store/calibration.ts:85-154`）；旧 accessor 用同一个键（`accessor.ts:13`，`BOT_MEMORY_KEY='Nexus'`）。旧域与主线子系统（`SUBSYSTEM_KEYS`，`memorySchema.ts:382`）并存于同一对象。唯一的小写读取是 `agents/index.ts:25`（`isWorkTile`），恒为 `undefined`，工位锁从不生效。

**另外**：旧孵化器仍在跑——`room.SpawnWork?.()`（`src/modules/agents/prototype/features.ts:46`，队列代码 `src/modules/spawning/legacy/spawnControl.ts:193-330`）与 `spawnDirector` 并行；`features.ts:41` 注释称已退役。

**核弹发射细节**：处理函数在 `features.ts:55` 的 `runFlagFeatures()` 中被调用，它运行在 `RoomFeatures.run` 的房间循环之前（`features.ts:68`）。一面 `nuke-*` 旗帜 + 一个可见己方房 → 每 tick TypeError → 本模块本 tick 中止，`MissionUpdate`、`SpawnWork` 与其余旗帜处理被跳过 → 连续失败后熔断整个模块 100 tick（`errorBoundary.ts:34,78`）。控制台 `nuker.launch`（`industry/console/nuker.ts:25-27`）同样坏。
