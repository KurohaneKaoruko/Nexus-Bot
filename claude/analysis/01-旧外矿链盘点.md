# 01. 旧外矿链盘点（`src/modules/external/*`）

> 2026-10-28 代码走查，未运行代码。结论被 `design/24-外矿迁移.md` §24.1 / §24.11 引用。

## 结论

外矿规划器与路网规划器在主线不运行。当前构建进入 `external/` 的活路径只有三条：

1. 收入提供方 `registerOutMineIncomeProvider`（`prototype/features.ts:33`）；
2. `getBuiltRoadCoverage`（`baseFunction.ts:516`），恒返回 0；
3. 控制台 `mine.*` / `road.*`。

主线的 `economy/remoteMining.ts` 不 import 任何 `external/` 代码。

## 1. 能力清单（未注明文件的均在 `externalMine.ts`）

- **入口**：`OutMine.outMine()`（`outMine.ts:20-30`）→ `prepareRoom`（`2290`，`room.memory.defend` / war 模式 / QoS 应急时停止）→ `EnergyMine` / `CenterMine` → `ExternalMine.runEnergy`（`2323`）、`runCenter`（`2483`）。运行间隔取自 `roomModeAccess.ts:67-144` 的 `remoteEnergyInterval` / `remoteCenterInterval`，由 `getRunState`（`626-636`）判断。
- **选点（0/1 背包）**：`computeManagedTargets`（`696-709`）合并 `energy` 与 `centerRoom` 列表，剔除不可达扇区（`62-69`），跑背包 DP（`423-573`），结果缓存 10 tick（`89`、`686`）。
  - 每源价值 = `ept − 矿工体型成本/剩余寿命 − dist·ept·0.04·(75|100)/1500 − 维修损耗`；
  - 每源重量 = `矿工部件数·1500/剩余寿命 + dist·ept·0.04·(1.5|2)`（`323-361`）；
  - 预定体：价值 −1.3 / 重量 +5；SK 房：价值 −4.5 / 重量 +50（`109-112`、`390-397`）；
  - 预算 = `spawn 数·500 − 本地预留`（`232-279`、`579-617`）；low 档上限 140 且 1 房；rush 档预算下限为满 spawn 容量且禁止中央房；
  - `runEnergy` 另有一道带 300 tick 迟滞的贪心筛选，存于 `room.memory.remoteKept`（`2350-2368`）。
- **自动扩点（仅 rush）**：`autoAddNearbyEnergyTargets`（`643-680`，调用于 `2339-2342`），列表为空且 RCL<8 时加入 4 个正交邻房（rush 为 8 个）。
- **孵化**：全部经 `addEconomyMission`（`1997`），只在 `getRemoteSpawnLeftover`（`1961-1994`，`spawn 数·500 − 本地需求 − 外矿已用`，按部件计）有余量时下单。
  - 采集体（`2075-2140`）：编制 = `源数 × min(每源上限, ceil(5/WORK))`，RCL≥4 每源上限 1，否则 3（`1556-1568`）；受可站位数约束（`1493-1516`，`Memory.rooms[x].sourcePosCount`）；替补只数 `ttl > 路程+15` 的采集体（`1838-1853`）；体型 `buildRemoteMinerBody(budget,5,…)`（`2137`），中央房固定 `W16C6M8`（`2119`）；每房最多 2 个挂单。
  - 搬运体（`2143-2199`）：采集体到岗后才孵（`1255-1274`）；全队上限 24，最多 3 个挂单。
  - 预定体（`2210-2226`）：RCL≥3，本方预定剩余 ≤1000 时派，一房一只。
  - 外矿建造（`2249-2284`）：存在路 / 容器工地或待修（<80% 血）时派 1 只，任务 >10 时 2 只；体型 `buildOutBuildBody`；「搬运饥荒」时暂停。
  - 侦察（`1875-1896`）：目标房无视野时派；无视野路径按记录的工位数继续补采集体（`2401-2416`）。
  - 每轮先删除上一轮的经济挂单（`clearPlannedEconomyMissions` `1714`，规则见 `externalScheduler.ts:94-102`），目标按「近者先、挂单少者先」排序（`externalScheduler.ts:115-125`）；不可达房的单位被要求自杀（`2372-2378`）。
- **搬运定编**：`buildCarryPlan`（`1121-1160`）：需求容量 = `Σ 2·dist·(ept − 维修损耗)·remoteCarryThroughputFactor`；只数 = `max(基数, ceil(需求/单只容量) + 积压加量)`，积压 ≥2000 加 1、≥3000 加 2，再乘 `remoteCarryBacklogScale`。`dist` 取已存路网路径长，否则 `20 + 25·线性距离 + 本地进场`（`946-962`）。离线回退 `calcEnergyOutCarryTarget`（`1571-1613`）用配置 `72-84`。单只容量（`1535-1553`）= `buildHaulerBodyConfig(cap,{forRoad:true,maxCarry:16})` 的 CARRY×50，rush 为 200。
- **外矿防御**：敌对单位（Invader、SK、带 ATTACK/RANGED 者，白名单除外）检测于 `2435-2449`。玩家威胁 → `doubleDefend`（`2050-2069`，RCL≥7 出 out-2attack + out-2heal，否则回落 `defend`）；`defend`（`2014-2047`）：out-defend 按 RCL 最多 3/2/1，invader core 出 out-invader 最多 4/3/2/1。`ranged`（`1918`）从未被调用。
- **中央九房 / SK 房与外矿元素矿**：`runCenter`（`2483-2555`）派 out-attack 护航、固定体型采集体、out-mineral（RCL≥6，一房一只，`2003-2011`）、搬运与建造。
- **路网（`externalRoad.ts`）**：`tryBuildRoad`（`externalMine.ts:720-744`）→ `ensureControllerContainer`（`externalRoad.ts:889-982`，注意这是**母房**控制器容器）→ `ensureContainerSites`（`873`）→ `createRoadSites`（`990`）。能源房 RCL≥4、中央房 RCL≥6 才修路，每 500 tick 重建（rush 100），每路线最多 10 个工地（`BaseConstant.ts:29-85`）。路径由 `PathPlanner.planPaths`（`629-705`，plain 2 / swamp 4 / road 1，maxOps 5000，CPU 90% 保护）从房间中心规划到各源（中央房另含元素矿，`1280-1301`）。`RoadMaintain`（`1375-1600`）**没有任何调用方**，旧构建下也是死代码。
- **搬运重平衡与收入分析**：`pickBestCarrySource`（`1162`）、`pickBestCarryTargetRoom`（`1289`，评分见 `externalScheduler.ts:161-212`）、`getRoomRemoteIncome`（`1370`，见第 4 节）。
- **可视化**：`runVisuals` → `RoadVisual.run`（`externalRoad.ts:1862`，`<room>/roadVisual` 或 `ALL/roadVisual` 旗帜触发）、`HighwayMineVisual.run`。都只从死掉的 `outMine` 进入，旗帜触发的绘制已失效；控制台一次性绘制仍可用。
- **bucket 门控**：`2429-2433`、`2537-2541`，用 `bucketGovernor.ts:44` 的 `getActiveRemoteThreshold`。

## 3. 运行时调用

- `outMine()`、`EnergyMine`、`CenterMine`、`runEnergy`、`runCenter`、`prepareRoom` 零调用方。`features.ts:45-47` 只调用 `MissionUpdate`、`SpawnWork`、`updateEnergyState`。`main.ts` 与 4 个 `branch/*/main.ts` 都用同一个 `RoomFeatures`。`extend(Room, OutMine)`（`Room/index.ts:23`）只挂方法；`room.interface.ts:694` 注释里的 `room exec()` 不存在。
- `externalScheduler.ts` 也是死代码，唯一引用方是 `externalMine.ts:23`。
- **旧外矿角色的行为已经不在了**：`CreepConstant.ts:70-277` 为 scout、reserver 与所有 out-* 声明了执行器，但 `roleRegistry`（`Creep/runtime/registry.ts:29-51`）一个都没有注册；这类单位会命中 `execute.ts:34-46` 的缺执行器日志并闲置。`out-2heal` 在 `combatHeal.ts:50` 有策略但未注册；`2247` 注释提到的 `out-build.ts` 不存在。
- `carrier.ts:1174` 与 `harvester.ts:304` 的外矿分支要求 `memory.sourceRoom` 与 `memory.targetRoom` 同时存在，活路径上没有任何地方同时写这两项（`spawnDirector.ts:477` 写 `{role, homeRoom}`；`mineMission.ts:52` 只为 power / deposit 角色写）。

## 4. `getRoomRemoteIncome`（`externalMine.ts:1370-1418`）

- 计算：对背包选中的每个房，收入 = `Σ 净 ept × min(采集比, 搬运比)`。采集比 = 在岗采集体 WORK×2 ÷ 净 ept（`984-1000`）；搬运比 = `sourceRoom` / `targetRoom` 匹配的搬运体容量 ÷ `Σ 2·dist·net·系数`（`1342-1356`）；无视野时 `min(10·记录源数, 同时带两字段的采集体数 × 5)`。
- **旧链不运行时恒返回 0**：列表为空得 `[]`；控制台填了列表也因搬运比为 0 而得 0。但它仍每 10 tick 跑一次 DP 与 `find`。
- **消费方**：`roomWorkforce.ts:402-432` 的 `estimateRoomEnergyIncome` 加上 `max(0, remote)`。因为返回的是数字 0，`427-428` 的回退估算（`min(20, harvester×5)`）被压掉——注册这个死提供方本身就让估算少了最多 20/tick。该估算只被旧孵化链读取（`spawnMission.ts:113`、`spawnRules.ts:219`；另见 `analysis/05` 第二部分第 3 条）。
